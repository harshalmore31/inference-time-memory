# LOCOMO benchmark for ITM

This directory holds the canonical evaluation harness and the small result
aggregates needed to reproduce the numbers in the top-level README's Results
section. The harness measures a controlled ablation of two memory behaviors;
it is not a head-to-head against other systems.

## What is committed

- `evaluate_memory.py` -- the harness. Ingests each LOCOMO conversation into a
  fresh `MemoryLayer`, recalls evidence per question with `recall_graph`,
  answers with an OpenAI model, and scores with token-F1 plus an
  LLM-as-judge. Per-conversation checkpointing.
- `results/locomo_memory_stats_{A0B0,A1B0,A1B1}.json` -- the three aggregate
  stat files for baseline, +A, and +A+B.
- `results/ablation_summary.json` -- a single consolidated summary of the
  ablation (per-config metrics, per-category accuracy, robustness, ceiling),
  reproduced directly from the per-question result files.
- `results/rejudge_mini_subsample.json` -- the paired `gpt-4.1-mini`
  re-judgment of a 200-question subsample (independent-judge robustness check).

## What is NOT committed (and why)

- The LOCOMO dataset (`benchmarks/locomo/`, ~22MB) -- download it separately
  (see below); it has its own license.
- The large per-question result files (`locomo_memory_results_*.json`, hundreds
  of KB to MB each) -- regenerated by a run.
- `results/logs/` -- raw run logs.
- The ad-hoc diagnostic and runner scripts (`diag_*.py`, `run_full_*.py`,
  `rejudge_mini.py`) -- these were used during development and are not part of
  the canonical, reproducible path. `evaluate_memory.py` is the supported
  entry point.

## Get the dataset

The harness expects `benchmarks/locomo/data/locomo10.json` (LOCOMO, ACL 2024).
Clone the LOCOMO repository into `benchmarks/locomo/`:

```bash
git clone https://github.com/snap-research/locomo benchmarks/locomo
# then confirm the file exists:
ls benchmarks/locomo/data/locomo10.json
```

## Run the ablation

Both toggled behaviors default OFF in `itm/config.py`. The harness reads them
from the environment so all three configs share one code path:

| Config | `ITM_TRANSCRIPT_INGEST` | `ITM_DEBIAS` | Tag |
|---|---|---|---|
| baseline | 0 | 0 | A0B0 |
| +A (transcript ingest) | 1 | 0 | A1B0 |
| +A+B (+ spreading debias) | 1 | 1 | A1B1 |

A run needs an `OPENAI_API_KEY` (put it in a `.env` at the repo root). The
answer model and judge model both default to `gpt-4.1-nano`.

```bash
# baseline
ITM_TRANSCRIPT_INGEST=0 ITM_DEBIAS=0 \
  python benchmarks/evaluate_memory.py \
    --data-file benchmarks/locomo/data/locomo10.json \
    --model gpt-4.1-nano --judge-model gpt-4.1-nano

# +A
ITM_TRANSCRIPT_INGEST=1 ITM_DEBIAS=0 \
  python benchmarks/evaluate_memory.py \
    --data-file benchmarks/locomo/data/locomo10.json \
    --model gpt-4.1-nano --judge-model gpt-4.1-nano

# +A+B
ITM_TRANSCRIPT_INGEST=1 ITM_DEBIAS=1 \
  python benchmarks/evaluate_memory.py \
    --data-file benchmarks/locomo/data/locomo10.json \
    --model gpt-4.1-nano --judge-model gpt-4.1-nano
```

Each run writes `results/locomo_memory_results_<tag>.json` (per-question, with
checkpointing) and `results/locomo_memory_stats_<tag>.json` (the aggregate).

To debug on a single conversation, add `--sample-id conv-26 --verbose`.

## Metrics

- Answerable accuracy is the judge score over categories 1-4 (multi-hop,
  temporal, open-domain, single-hop). Category 5 is adversarial (the correct
  answer is a refusal) and is reported separately; folding it into an "overall"
  number inflates a refusing baseline, which is why the README leads with the
  answerable split.
- `gold_present` is whether at least one of the question's annotated evidence
  turns appeared in the recalled top-k -- this isolates retrieval quality from
  answer-model quality.
- `judge_when_gold_present` is the answer model's accuracy given that gold
  evidence was retrieved. At +A+B this is ~37.6%, the answer-model ceiling.

## Robustness checks

- Refusal-hardened re-scoring: force a refusal on an answerable question to a
  wrong score before averaging. The slope holds (3.51% -> 19.74% -> 30.58%).
- Independent judge: a paired 200-question subsample is re-graded with
  `gpt-4.1-mini` on the SAME stored predictions (no regeneration). Its output
  (`results/rejudge_mini_subsample.json`) is committed; the re-grading script
  itself is a development diagnostic and is not part of the supported run path.
  The improvement direction survives the judge swap; nano-vs-mini agreement is
  0.745 on the judged pairs, and the mini judge is more lenient on the
  baseline.

## Caveats

Single seed, no error bars, `top_k=5` (a lower bound). The numbers are a
relative-improvement ablation, not SOTA-competitive absolute accuracy. See the
top-level README's "Honest ceiling and limitations".
